# depgraph — граф зависимостей Maven-пакета

Практическая работа №2 «Конфигурационное управление», вариант 9.

## Общее описание

Консольный инструмент строит граф зависимостей Maven-пакета (с учётом
транзитивности), выводит порядок загрузки зависимостей и описание графа
на языке Mermaid. Зависимости читаются напрямую из `pom.xml` в репозитории
Maven; менеджеры пакетов и сторонние библиотеки не используются — только
стандартная библиотека Python 3.10+ (`urllib`, `xml.etree`, `configparser`).

Что учитывается при разборе `pom.xml`: родительские pom (`<parent>`),
свойства `${...}` (в т. ч. `${project.version}`), `dependencyManagement`.
Пропускаются зависимости со scope `test`, `provided`, `system`, `import`
и `<optional>true</optional>`.

## Настройки (INI-файл, секция `[depgraph]`)

| Параметр | Обязателен | Описание |
|----------|:----------:|----------|
| `package` | да | `groupId:artifactId:version`; в тестовом режиме — имя из заглавных латинских букв |
| `repository` | да | URL репозитория (`http://`, `https://`, `file://`) или путь к файлу тестового репозитория |
| `test_mode` | нет | `true`/`false` (по умолчанию `false`) — режим тестового репозитория |
| `filter` | нет | Подстрока: пакеты, в имени которых она есть, не анализируются (вместе с поддеревом) |

Неизвестные параметры, пустые значения, неверный формат имени, не-URL,
отсутствующий файл тестового репозитория и т. п. приводят к сообщению
`Ошибка: ...` и коду возврата 1.

## Команды

```sh
./run.sh -c examples/httpclient.ini -s graph     # или: make run SHOW=graph
```

| `--show` | Этап | Что выводит |
|----------|:----:|-------------|
| `config` | 1 | Параметры в формате «ключ = значение» |
| `direct` | 2 | Прямые зависимости пакета |
| `graph` (по умолчанию) | 3 | Весь граф: `пакет -> зависимости` в порядке BFS |
| `order` | 4 | Порядок загрузки (зависимости раньше зависящих) и рёбра-циклы |
| `mermaid` | 5 | Описание графа на языке Mermaid |

Сборки не требуется. Запуск тестов: `make test`
(или `PYTHONPATH=src:tests python3 -m unittest discover -s tests -v`).

## Алгоритмы

* **Граф (этап 3)** — BFS с рекурсией: один вызов обрабатывает целый слой
  и рекурсивно вызывает себя для следующего. Уже встреченный пакет повторно
  не раскрывается, поэтому циклы и самозависимости не зацикливают обход
  (рёбра цикла в графе остаются).
* **Порядок загрузки (этап 4)** — обход в глубину (итеративный),
  пакет попадает в список после всех своих зависимостей; корень — последний.
  Рёбра, замыкающие цикл, игнорируются и выводятся отдельно.
* **Тестовый режим** — файл вида `A: B C` (A зависит от B и C), `#` —
  комментарий. Примеры — `examples/test-repo-*.txt`.
* Пакеты с разными версиями — разные узлы графа (разрешения конфликтов
  версий, как в Maven, нет).

## Примеры

Тестовый репозиторий с циклом (`examples/test-repo-cycle.txt`):

```
$ ./run.sh -c examples/test-mode.ini -s graph
A -> B, C
B -> D
C -> D, E
D -> A
E -> (нет зависимостей)

$ ./run.sh -c examples/test-mode.ini -s order
1. D
2. B
3. E
4. C
5. A
Цикл: D -> A (ребро пропущено)
```

Фильтр (`filter = D`) убирает пакет D:

```
A -> B, C
B -> (нет зависимостей)
C -> E
E -> (нет зависимостей)
```

Локальный Maven-репозиторий `tests/fixtures/repo` (есть родитель, свойства,
dependencyManagement, test/provided/optional-зависимости и цикл
`liba -> libc -> liba`):

```
org.example:app:1.0 -> org.example:liba:1.0, org.example:libb:2.0
org.example:liba:1.0 -> org.example:libc:1.0, org.example:libb:2.0
org.example:libb:2.0 -> org.example:libc:1.0
org.example:libc:1.0 -> org.example:liba:1.0
```

## Этап 4. Сравнение порядка загрузки с Maven

Для сравнения с реальным менеджером пакетов:

```sh
mvn dependency:tree -Dscope=runtime          # дерево зависимостей
mvn dependency:build-classpath               # порядок на classpath
```

Ожидаемые причины расхождений с выводом `--show order`:

1. Maven разрешает конфликты версий по правилу «ближайшее определение
   побеждает» и оставляет один артефакт на пару groupId:artifactId;
   у `depgraph` разные версии — разные узлы.
2. Maven учитывает `<exclusions>`, BOM-импорты (`scope=import`),
   диапазоны версий и профили; `depgraph` их пропускает
   (версия-диапазон → предупреждение и пропуск).
3. Порядок на classpath у Maven — по порядку объявления (прямые
   зависимости раньше транзитивных), а не «зависимости раньше зависящих».
4. Maven не бросает ошибку на циклах между артефактами так, как
   топологическая сортировка: `depgraph` явно печатает пропущенные рёбра.

## Этап 5. Визуализация

```sh
./run.sh -c examples/httpclient.ini -s mermaid
./run.sh -c examples/jackson-databind.ini -s mermaid
./run.sh -c examples/slf4j-simple.ini -s mermaid
```

Вывод вставляется в <https://mermaid.live> или в Markdown-блок
```` ```mermaid ````. Для сравнения со штатным инструментом:
`mvn dependency:tree -DoutputType=dot` — расхождения объясняются
пунктами 1–2 выше (Maven показывает «победившие» версии и пропущенные
дубликаты, `depgraph` — полный граф по прямым записям pom).

## Структура

```
src/depgraph/   исходный код (config, pom, maven, testrepo, graph, order, mermaid, cli)
tests/          модульные тесты и локальный Maven-репозиторий (fixtures)
examples/       примеры конфигураций и тестовых репозиториев
run.sh, Makefile
```
